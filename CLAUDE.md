# CLAUDE.md

## Що робить проєкт

`Chess-games` — невеликий набір незалежних статичних навчальних сторінок для учнів
шахової школи (yaroslavchess.com). Кожна сторінка — окремий самодостатній HTML-файл без
збирання й без бекенду. Зараз їх дві:

- **`knight-quest/`** — гра «Хід Конем» (інтерфейс українською). Кінь стартує з a1 і має
  дійти до зеленої цілі, обходячи заблоковані поля. 10 рівнів (заблоковано 3…30 полів,
  `BLOCKED_COUNTS`), рівні генеруються детерміновано (`generateLevel`, зерно від номера
  рівня) і перевіряються пошуком у ширину (`bfsReachable`) на досяжність. Рахує ходи й час,
  зберігає рекорди й прогрес. Ходи — натисканням або перетягуванням коня.
- **`english/unit2/`** — тренажер англійської «Unit 2: In the Spotlight» (інтерфейс
  англійською, переклади німецькою — поле `de`). Чотири режими: Core Vocab, Comparison
  Traps, Adverbs & Mine/Yours, Collocations. Дані — масиви в самому файлі
  (`FULL_DATABASE`, `COMPARISON_TRAPS`, `ADVERB_DATA`, `PRONOUN_DATA`, `COLLOCATIONS_DATA`).
  Озвучення слів через браузерний `speechSynthesis` (`en-GB`), сесія з повтором помилок.

## Структура файлів

```
knight-quest/index.html    гра «Хід Конем» (HTML + CSS + скрипт, фігурка коня вбудована як data:-URI)
english/unit2/index.html   тренажер англійської, Unit 2
README.md                  короткий опис для людини
CLAUDE.md                  цей файл
```

Нова сторінка = нова папка з власним `index.html` (за зразком наявних). Спільного коду,
пакетів і конфігів збирання немає.

## Як запускається

Збирати нічого не треба. Відкрити потрібний `index.html` у браузері або з кореня
репозиторію виконати `python3 -m http.server 8000` і перейти на
`http://localhost:8000/knight-quest/` чи `http://localhost:8000/english/unit2/`.
Публікація — GitHub Pages з кореня (шляхи `/knight-quest/`, `/english/unit2/`); налаштування
Pages у репозиторії не перевірялись.

## Правила, яких не можна порушувати

Це не формальна специфікація, а те, що видно з коду й історії; тримайтеся цього, доки
власник не скаже іншого.

- **Кожна сторінка — один самодостатній `index.html`** (HTML, CSS, скрипт разом), без
  збирання, npm і фреймворків. Не виносити спільний код між сторінками без прохання.
- **Мова інтерфейсу не змішується:** `knight-quest` — українська, `english/unit2` —
  англійська. Не перекладати одне на іншу мову.
- **Мобільні браузери, зокрема Safari/iOS:** лишати `<!DOCTYPE html>`, `viewport`,
  запасний варіант для `aspect-ratio` (див. коміт про Safari у `knight-quest`). Нічого не
  має ламатися на ширині 375 px, горизонтального скролу немає.
- **Навчальні дані не вигадувати вільно:** слова, переклади й граматичні пастки в
  `english/unit2` відповідають сетам курсу (Sets 1–26 у коментарях файлу); дописуйте або правте їх лише
  за вказівкою власника й зберігайте структуру записів (`{ en, de, cat }` тощо).
- **Приватність:** персональних даних не збирати, аналітики й трекерів не додавати.
  Єдине сховище — `localStorage` у `knight-quest` (ключ `hidkonem_progress_v2`: прогрес і
  рекорди, у `try/catch`). Якщо міняєте формат прогресу — змініть версію ключа. Зовнішні
  запити — лише шрифти Google Fonts у `knight-quest`; нових зовнішніх ресурсів не додавати
  без згоди власника.
- **Стиль JS:** у `knight-quest` — класичний ES5 (`var`, `function`, IIFE, без `=>`); в
  `english/unit2` — сучасний JS (`const`/`let`, стрілкові функції, шаблонні рядки). Пишіть
  у стилі файлу, який правите, і не переписуйте один файл під стиль іншого.
- **Не мерджити PR і не відкривати його без прохання власника.**

## Як перевірити зміни

Автотестів і лінтерів у репозиторії немає, перевірка ручна:

1. Відкрити змінену сторінку (локально або через `http.server`) і пройти основний сценарій:
   - `knight-quest`: пройти рівень 1, перейти на наступний, перезавантажити сторінку
     (прогрес збережено), «Почати рівень заново», «Скинути весь прогрес».
   - `english/unit2`: пройти кілька карток у кожному з чотирьох режимів, перевірити
     озвучення (🔊), завершення сесії й «Practise Only … Missed».
2. Емуляція телефона на ширині 375 px (Playwright або DevTools): без горизонтального
   скролу, дошка й кнопки доступні пальцем.
3. У консолі немає помилок.
4. Якщо правили дані `english/unit2` — переконатися, що в кожного запису є всі поля і
   немає дублікатів.
5. Для `knight-quest` після зміни генератора рівнів переконатися, що кожен рівень досяжний
   (перевіряє `bfsReachable`) і що рівні лишаються однаковими між запусками (детерміноване
   зерно).
